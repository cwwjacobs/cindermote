# Unresolved Risks & Known Limitations

1. **Hardware / Host Isolation Gate**: In containerized environments lacking `/dev/kvm`, live Firecracker VM detonation cannot execute and returns `INFRASTRUCTURE_FAILED` or `SKIPPED`. Full hardware containment requires a bare-metal Linux 6.18 host with `/dev/kvm` enabled and host swap disabled.
2. **Provider Side-Channel & Data Retention**: External model endpoints (e.g. OpenAI/DeepSeek) receive prompt text inside TLS tunnels. Content retention or logging by third-party model providers remains an external risk outside Cindermote's local kernel boundary.
3. **Multi-Tenant SaaS Control Plane**: The control plane (web UI, multi-tenant billing, OAuth) is out of scope for the core kernel spine and must be isolated from raw guest semantic relay paths when built.
4. **Detection efficacy is unmeasured.** agent-probe records whether a sacrificial model, given one `skill.md`, proposed a prohibited action in one run. No labeled benign and malicious corpus has been run, so there are no published true- or false-positive rates. The system prompt tells the model the file may be hostile, which may lower the injection success rate; that effect has not been measured. A model that resists the injection yields `ALLOW` with the artifact left on `HOLD`.
5. **Receipts are not third-party verifiable.** Signed envelopes use HMAC-SHA256 with a host-local key. Anyone holding the key can forge receipts, and a verifier needs the key. Asymmetric signatures (and a key held outside the probe host) are not implemented.
6. **The legacy profile shares the host kernel.** The namespace runner (chroot, seccomp, ptrace, cgroups) is deprecated and is not a microVM boundary. As root it needs a real cgroup v2 mount; unprivileged runs are explicitly degraded.
7. **Guest evidence records are limited to 64 KiB.** A provider response larger than one secretstream chunk makes the guest evidence sealer fail (`GUEST_FAILURE`, reported as an infrastructure failure, never `ALLOW`). The guest's 128 KiB tool-argument limit is therefore unreachable. Changing it edits a hash-pinned guest source and needs a rootfs rebuild and re-pin.
8. **Guest rootfs freshness.** The guest image pins a dated Debian snapshot (Chromium `150.0.7871.124`). It will accumulate unpatched CVEs until it is rebuilt and re-pinned; there is no scheduled rebuild or image vulnerability scan yet.
9. **Pinned assets depend on third-party hosting.** The Firecracker release and the guest kernel are downloaded from GitHub and Firecracker's CI bucket and verified by SHA-256. If either disappears the build fails closed; there is no mirror.
